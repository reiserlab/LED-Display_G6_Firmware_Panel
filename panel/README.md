# panel — G6 panel firmware

The production firmware for a Generation-6 LED-display panel (20×20, RP2354 /
RP2350 core). The panel is an **SPI peripheral**: the arena controller streams
display frames over SPI (MODE3) and the panel renders them on its LED matrix.

For the build/flash/monitor workflow (pixi tasks, PlatformIO env matrix,
hardware-rev notes), see the parent [`../README.md`](../README.md). This file
documents the firmware itself.

## Two-core architecture

- **Core 0 — SPI ingest** (`messenger.cpp`, `panel_spi_custom.cpp`):
  a DMA-paced RX captures each frame; `Messenger` then runs the validity gate
  (parity → length → protocol → opcode) and either dispatches the frame to the
  display queue or raises a `PEnn` error glyph.
- **Core 1 — display** (`display.cpp`, `bcm.cpp`, `display_scan_twopio.cpp`):
  pulls patterns off the queue and drives the LEDs with binary-code-modulation
  (BCM) grayscale via a DMA-fed two-PIO scanner (rows on PIO1, columns on PIO0).

The two cores communicate through lock-free `queue_t` rings (display patterns
and error-glyph slot indices).

## Build flags

- `PANEL_REV` — `31` (v0.3.1, the only supported rev); selects pin map and SPI block.
- `RP2350_PSRAM_CS` — PSRAM chip-select GPIO (per rev).
- `SPI_DIAG=1` — enable the SPI timing + validity-gate serial diagnostics in
  `messenger.cpp` (off by default; see parent README).
- `STAGE2_SELFTEST=1` — BCM-via-PIO visual self-test; **no SPI ingest, do not
  deploy** for bench testing.
- `SCAN_BANK_WINDOWS_DEFAULT=1` — boot into the bank-window scan
  (`pico_v031_bankon`); otherwise every boot starts in legacy scan.
- `PANEL_CONSOLE=1` — production SPI ingest plus a USB console for the
  bank-window scan (`pico_v031_bankwin`); bounds the SPI bus waits like
  `SPI_DIAG` so the console runs while the bus is idle.

## Tools (`tools/`)

- `g6_flash.py` — flashes new/blank *and* running panels; driven by the
  `flash*` pixi tasks (see parent README's Flash & monitor section).
  `picotool`-based on Linux (one or many, in parallel); on macOS a 1200-baud
  BOOTSEL touch + UF2 copy to `/Volumes/RP2350` (one panel per invocation).
- `build_release.py` — builds UF2 + ISP `.bin` + `manifest.json` for a
  catalog discovered from `platformio.ini` (`extends = common` -> `release`;
  `extends` another `pico_v*` env -> `diag`); the `release`/`diag` pixi
  tasks. `--list` shows the discovered catalog.
- `make_isp_image.py` — wraps a built firmware in the 32-byte ISP footer for
  the arena controller's over-SPI reflashing.
- `monitor.py` — open a serial console on a specific panel by USB serial
  number, cross-platform; the `monitor` pixi task.
- `gen_predef_patterns.py` — generate the predefined-pattern blob + slot header
  (run automatically as a PlatformIO pre-build script).

## Bank-window scan (LAB-286)

On the four-color v0.4 panel each electrical column is one LED bank
(`bank = sch_col % 4`: T0 violet, T1 blue, T2 green, T3 yellow-orange) and every
row holds 5 LEDs of each bank. The legacy scan lights a whole row (up to 20 LEDs)
at once, and the row driver's drop costs a fully lit row ~11% of its light. The
bank-window scan lights one bank at a time inside each row slot (window T0, then
T1, T2, T3), so at most 5 LEDs conduct (row current ≤ ~0.12 A).

- **Where it lives:** the column SM is unchanged; a bank-window row is just more
  `{col_word, delay}` planes in the column DMA stream (`bcm_plane_data`, up to 16
  per row): 4 planes for Gray_2, 16 for Gray_16 (bit-planes 1, 2, 4, 8 inside each
  window). The row SM holds the row for the sum, as before.
- **Window table:** ns at duty 255 and the 3.0 µs base. Default (Option B):
  `4200, 5500, 12700, 22500` (sum 44.9 µs vs the legacy 45 µs row). Duty scales
  every window; Triggered's 1.0 µs base scales them by 1/3. A window of 0 keeps
  that bank dark. Limits: each ≤ 45000 ns, sum ≤ 48000 ns.
- **Timing at 150 MHz, duty 255:** row burst 6743 cycles (Gray_2) / 6767
  (Gray_16) vs legacy 6752 / 6758; the frame is still padded to 1000 µs. The
  Gray_16 LSB is window/15 (violet 42 cycles = 280 ns); a plane lights at least
  5 cycles (33 ns), which the violet LSB reaches below duty ≈ 30.
- **Control:** `ScanConfig {mode, window_ns[4]}` requested on core 0
  (`scan_config_request()`), applied by core 1 before its next frame. RAM only:
  every boot starts in legacy scan. The firmware cannot tell a four-color panel
  from a green-only one, so nothing enables it automatically; on a green panel,
  `W11225,11225,11225,11225` gives four equal groups by `col % 4`.
- **Trial build** `pico_v031_bankon`: production (SPI ingest, ISP, no console)
  that boots straight into bank windows with the Option B table, for running a
  whole row of four-color panels from the arena. Four-color panels only.
- **Console** (`pico_v031_bankwin`; `B`/`W` also in `pico_v031_bcmtest`):
  `B` status, `B0`/`B1` legacy/bank windows, `W<t0>,<t1>,<t2>,<t3>` window table,
  `S` frame timing since the last `S`, `?` help.
- **Not built yet:** an arena command (a V2 opcode carrying `u8 mode + 4×u16 ns`
  maps directly onto `scan_config_request()`); per-row droop compensation (scale
  each window's delays by a gain indexed by the LEDs lit in that row and bank —
  the hook is marked in `precompute_bank_data()`); giving single-bank rows the
  whole slot (per-row plane counts in `twopio_scan_row()`).
